# Chat History Future

## 機能概要

このドキュメントは、履歴付きチャットを将来導入する場合の位置づけを整理するための設計メモです。初期実装対象ではなく、MVP の責務分離を壊さないための前提整理を目的とします。

## 基本方針

- 履歴付きチャットは `Chat Once` へモード追加せず、別責務として扱います
- 会話状態の保持、messages 配列の構築、送信は分離する方向を優先します
- 単発ノードは「毎回独立」の性質を保ち、履歴管理の複雑さを持ち込まないようにします

## 想定する責務分割

### 履歴保持ノード

会話履歴を保持、追加、リセットする責務を持ちます。ComfyUI 上での状態保持方法は実装時に要検討ですが、少なくとも単発送信ノードとは分けます。

### messages 構築ノード

system、user、assistant、画像入力などを配列へ組み立てる責務を持たせる案です。将来的に高度な制御が必要になった場合、この層で吸収しやすくなります。

### 送信ノード

送信ノードは完成済み messages を受けて API へ送る役割に寄せることも可能ですが、MVP では過剰設計になりやすいため、初期実装には持ち込みません。

## 将来検討する項目

- 履歴の永続化単位
- assistant 応答の再投入方法
- token 上限に応じた履歴トリミング
- 画像付き履歴の扱い
- ワークフロー再実行時の状態再現性

## 注意点

- 履歴付きチャットは便利ですが、ComfyUI の静的ワークフローに状態管理を持ち込むため複雑さが増します
- 初期段階では単発送信の使いやすさと安定性を優先します
- 将来実装する場合も、接続設定、プリセット、単発送信の責務を壊さないことを優先します
